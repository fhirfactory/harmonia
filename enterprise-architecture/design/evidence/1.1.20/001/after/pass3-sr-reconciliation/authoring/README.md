# Reproducing Pass3/013

These are evidence-local scripts for this bounded incorporation, not new governed tooling or a metamodel extension. Run from the repository root with Python 3; no third-party packages are required:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 enterprise-architecture/design/evidence/1.1.20/001/after/pass3-sr-reconciliation/authoring/build_result.py
PYTHONDONTWRITEBYTECODE=1 python3 enterprise-architecture/design/evidence/1.1.20/001/after/pass3-sr-reconciliation/authoring/verify_result.py
```

The builder checks the pinned Pass3/012 package before reading it and writes only this Pass3/013 directory. `changes.json` exposes all seven CT3 refinements, 33 Feature refinements and the five source-to-target consolidations for review. Surviving Feature names and all original criteria remain unchanged. Canonical Markdown is transformed only at those definitions, the retired source block and the working-candidate preamble. The existing qualified contribution annotation is carried unchanged to the clinical handover survivor; its source block remains in retirement evidence.

The workbook reader supports string, inline-string and shared-string cells. Original XD, FR, screening and history worksheet bytes are retained. The original SR narrative and reconciliation exceptions are snapshotted as History P012 sheets before updating their current counterparts. Measurement rows retain all 2,941 source criteria with active target correspondence, including five retired source identities. Deterministic ZIP member timestamps make repeated builds byte-reproducible; they assert no provenance event time.

The verifier checks the source/result transition and source criteria, not implementation. It loads the source and result with standard-library OOXML tooling, checking ZIP/XML/internal relationships/cells/data, and verifies unaffected definitions and all XD elements. It does not claim full ECMA-376 XSD validation, office application load/export, visual inspection or Solution Architect acceptance. The inherited external-office qualification remains unresolved.

The source/result manifest pins inputs and reproducible result data. The formal Task/Report records remain under this iteration's before/after provenance locations. Reports and iteration-evidence checks are finite event records and are not regenerated by the builder.
