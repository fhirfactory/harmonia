# F-01 implementation gap analysis — iteration 003

**Inspected candidate** · `feature/BL-CALLIOPE-OO-01`, HEAD `fd52408e3d8be433bb43eedd2a448354646d7518`  
**Comparison** · Existing Calliope model and selected callers versus [Draft.001.002][draft]

This analysis updates the material exceptions in [iteration 002][previous]. Source and test inspection was limited to the naming model, selected direct consumers and the Maven dependency declarations. The [architecture reconciliation][reconciliation] identifies the dispositions required for dependent work.

## Material exceptions

| Area | Observed contract | Gap and consequence |
| --- | --- | --- |
| **Topic identity and field validation** · F-01.1–F-01.4, F-01.48–F-01.56 | `Topic` requires a UUID, exposes `getId()` and `getShortId()`, and returns a sorted map from `getCanonicalName()`. Actual equality and hashing already ignore UUID and compare the map. `TopicEntry` rejects blank qualifier/name, trims both with `trim()`, has no version, and is extensible. `Topic` copies the map and retains its supplied entries. [Topic][topic] · [TopicEntry][entry] | Use ordered immutable field records and reversible non-versioned identity text, with version-independent natural ordering. Keep value rejection and replace trimming with exact character and whitespace validation. Measure decoded values in Unicode code points after checking well-formedness. Support optional ASCII versions and preserve their separate meaning. Assess UUID and accessor compatibility under R1 and R4. |
| **Qualifier generation and Topic parser inputs** · F-01.48–F-01.56, F-01.68 | `TopicBuilder` immediately constructs a `TopicEntry` that rejects missing/empty qualifiers. Legacy `TopicFactory.fromName` trims input and supplies named positional qualifiers for bare segments, using `Level<i>` beyond its fixed set. This corrects the iteration-002 characterization of the current factory. Some five-coordinate constructors and factories supply domain-specific fallback values. [Builder][topic-builder] · [Factory][topic-factory] · [Topic][topic] | Allow only null/empty qualifier input at generic assembly, resolving and validating `N<position>` at final build. Reject missing/empty generic values immediately. Canonical parsing requires explicit completed fields. Identify legacy conveniences whose callers depend on bare-path inference or domain defaults and obtain an adapter disposition before translating those inputs. |
| **Topic builder modes and replacement** · F-01.65–F-01.73 | Sequential adds delegate to indexed adds at the next key, so current code mixes the modes. The builder rejects negative positions, duplicates and final gaps. `build()` passes the map to a copying Topic constructor. The current TopicBuilder test explicitly requires duplicate rejection. [Builder][topic-builder] · [Topic][topic] · [Builder test][test-builder] | Fix mode on the first successful add and keep failures atomic. Preserve final continuity checks. At an occupied index, validate the new input before replacing it. Test failure recovery, indexed order independent of call order, and immutable snapshots even with newly introduced optional fields. No removal or builder-from-Topic method is required. |
| **Universal kind and ordinary invariants** · F-01.45, F-01.57–F-01.60 | `TopicMask` stores UUID, alternative pattern maps and Exact/Inclusive. Its constructor prefers a nonempty canonical map when both are supplied. Null depth policy defaults Inclusive. An empty Inclusive mask matches every non-null Topic. The builder can build empty. `unrestricted()`, `nameBased(null)` and default parsing of null, blank, `*` or `.*` all reach an empty Inclusive representation. [TopicMask][mask] · [Builder][mask-builder] · [Factory][mask-factory] | Make universality explicit and carry it through logical reconstruction. Reject empty ordinary masks and ambiguous data. Match null as false for both kinds. Reconcile old unrestricted intent and migrate only according to R2. Broad ordinary expressions remain ordinary and honour depth, containment and version presence. |
| **RegEx and literal construction** · F-01.57–F-01.67 | Canonical patterns reject blank qualifier/name RegEx and trim supplied expressions, then compile Java `Pattern`. Name-based builder input can reach stored state without syntax validation. Name matching calls `String.matches` at evaluation, except for a `.*` shortcut. The current helper surface has no validated literal or version overloads. [Entry pattern][pattern] · [TopicMask][mask] · [Builder][mask-builder] | Validate and compile immutable entries with RE2/J as they are created. Keep original RegEx, including empty strings, while rejecting null qualifier/value RegEx. Preserve three version-constraint states and report the kind distinctly on reconstruction. Validate literals as completed TopicEntry fields before quoting and checking expression limits. A null/empty version is invalid in the three-argument literal helper. Dedicated wildcard helpers have explicit behaviour. |
| **Canonical text and interchange** · F-01.15–F-01.16, F-01.25–F-01.28, F-01.46, F-01.56–F-01.59 | Jackson creator/property shapes expose UUIDs and keyed Topic entries or alternate mask maps. Naming factories split on dots and trim, with a special grouping rule for some numeric version-looking segments. Current canonical formatting does not protect field delimiters. `TopicMask.matches(String)` reparses through the legacy Topic factory. `TopicMaskEntryPattern` recompiles transient patterns during matching if they are unavailable after reconstruction. [Topic][topic] · [TopicMask][mask] · [Topic factory][topic-factory] · [Mask factory][mask-factory] · [Entry pattern][pattern] | Provide strict Topic parsers and a distinct mask-expression decoder. Preserve exact fields and raw RegEx through both escaping layers, including empty version expressions. Ordinary mask text requires a separate containment flag. Logical universal decoding requires the explicit kind. Reconstruct through validation and compile once. Keep current JSON round trips as characterization of the old shape and prove adapter correspondence separately. |
| **Navigation, bounded evaluation and diagnostics** · F-01.29–F-01.42, F-01.47 | `Topic` offers basic name, depth and coordinate accessors without the versioned canonical, display, parent/ancestor or natural-order contract. The inspected naming matcher short-circuits some depth/position checks but has no release-defined length/complexity verification, fail-closed exception mapping or application LogEvent path. [Topic][topic] · [TopicMask][mask] · [Entry pattern][pattern] | Add the specified projections and preserve retained versions during navigation. Verify depth-first, field-ordered short circuit, bounded RE2/J behaviour, concurrent reuse and application diagnostics. The existing five-coordinate `getModelVersion()` is a path value and has distinct semantics from a TopicEntry's optional version. No new log or result-cache infrastructure is required. |

## Consumer exceptions

- **Security and composed masks.** InformationUnitMask and OperationalMetadataMask hold TopicMasks for governed data. InformationSecurityContext converts representative action names through `TopicFactory.fromName` and `TopicMaskFactory.nameBased`, which consumes a name as a pattern. Confirm authorial intent and test scope when selecting literal or RegEx adapters. A failed inner selector definition cannot be silently interpreted as absent or unrestricted. [IU mask][iu-mask] · [Operational mask][om-mask] · [Security context][security] · [R2][reconciliation]
- **IU designation and transport names.** The current IU factory builds `Domain=harmonia.Model=mneme.ModelVersion=iu.DataElement=<hex>` from its processed ID. The IU identifier also parses the unqualified Topic projection. The Ergon FHIR converter consumes legacy text with `fromName`, and Ponos emits `toTopicString()` in `HIE_TOPIC`. Establish approved mappings and demonstrate compatibility at actual boundaries before changing text or stored references. The observed factory does not supply R3 authority. [IU identifier][iu-id] · [Topic factory][topic-factory] · [Ergon FHIR converter][fhir] · [Ponos producer][ponos]
- **Subscriptions and dependency allocation.** `TopicSubscription` has its own trimmed, case-insensitive literal and wildcard rules. Praxis seeds legacy subscriptions, and Ponos asks registered workflows to match their Topics. Test retained or migrated semantics before changing route eligibility. The inspected Maven declarations have no RE2/J entry. Allocate the dependency and application logging under R5, then verify pinned engine capabilities and R6 logging behaviour. [Subscription][subscription] · [Praxis seeding][praxis] · [Ponos dispatch][dispatch] · [Calliope POM][pom] · [R5–R6][reconciliation]
