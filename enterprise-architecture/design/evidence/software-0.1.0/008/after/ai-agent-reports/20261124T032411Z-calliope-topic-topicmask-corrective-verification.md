## Confirmed corrective defects

### TopicMask JSON and nested consumers · DR-2, DR-3 and DR-4

The checks used the candidate's Jackson 2.17.0 with annotations enabled, with default JSON parser settings and JavaTimeModule where the consumer uses it. The positive controls used a one-entry exact ordinary mask that matched only the selected Topic and explicit valid universality that matched both test Topics. All seven sampled malformed **inner** shapes rejected through direct binding and in security action, operational subject and IU identity properties. Root and security collection element nulls rejected. The following failures occurred outside the scope of the streaming mask object:

| Boundary | Reproduced result | Significance |
| --- | --- | --- |
| Standalone Jackson document | A valid universal object followed by a second root value or by invalid trailing text returned a universal mask. Enabling `FAIL_ON_TRAILING_TOKENS` on the standalone reader rejected the second root. | The decoder validates its object through `END_OBJECT`. Whole-document validation depends on the reader. |
| Tree-first Jackson binding | Default `readTree` collapsed conflicting discriminator members. `treeToValue` then accepted the surviving universal object. Strict duplicate detection rejected the raw input before tree construction. | The decoder cannot recover members discarded before binding. No production tree-first TopicMask route was established in the inspected code. |
| Enclosing consumer properties | Repeating `actionTopicMasks`, `subjectMask` or `identityMask` with an ordinary criterion followed by a universal one selected the second value. The operational and IU controls supplied the other mask properties to isolate duplicate handling. Repeating the action collection with null second erased the first criterion. Raw strict duplicate detection rejected the tested enclosing duplicate. | Bean-level binding can change selection even though each visited mask object is decoded strictly. Nested security in `InformationMetadata` and the actual V001 `InformationUnitConstructor` reproduced replacement with the universal action. The V001 check used a synthetic local record with matching digest and independently valid IU key, and establishes decoder behaviour only. |
| Optional `OperationalMetadataMask` and `InformationUnitMask` criteria | Explicit null **and omitted** TopicMask properties failed with the strict decoder's mapping exception. A current operational mask written with only a subject criterion failed when read back because the optional context criterion was omitted. IU identity-only input had the same absence failure. The default/JavaTime-only IU writer had an additional `Optional<TopicMask>` serialization failure. | Jackson 2.17.0 uses the inherited absent-value path, which delegates to the decoder's rejecting null handler. The corrective report's claim that explicit optional null becomes absent was not reproduced. These are valid ordinary model shapes with optional criteria. |
| Alternate security constructor paths | Jackson coerced boolean and numeric elements in the legacy `actionMasks` array to strings and constructed literal action criteria. The Java security-context builder discarded a supplied null typed element, while direct JSON binding and the constructor reject null typed elements. | The legacy-name path never calls the TopicMask JSON decoder. The builder normalizes criteria before they reach the constructor. These paths do not manufacture a universal TopicMask, but they can synthesize or remove security selection criteria. |

Disabling Jackson annotations alone made both ordinary and universal objects unconstructible. Source inspection found no registered alternative TopicMask binder, annotation-disabling configuration or mix-in for the supported consumers. A diagnostic-only mapper with trailing-comma support accepted that syntax before the decoder saw tokens. The private TopicMask constructor, canonical and legacy factories, and standard Java proxy provide no in-scope path from empty ordinary criteria to universality. The observed widening is in JSON framing and enclosing binding. The tested security structures are neutral criteria. No changed Themis decision or live routing result was established. ### Ergon interchange · DR-3 and DR-4

- The configured `readTree` accepts a valid current Topic JSON object followed by a second root or invalid trailing text. A predecessor object with a conflicting depth larger than the 32-bit range was accepted when its `intValue()` equalled the true depth. The predecessor JSON literal `null` used to return absence through the actual HEAD converter. The corrected dispatch interprets it as the literal `Domain=null` Topic. Complete JSON framing, exact derived checks and classification of the historical null form remain open. [Interchange][ergon]
- A valid depth-32 Topic with escape-heavy fields at their individual limits produced 24,671 code points in versioned canonical text and 25,901 in JSON. The writer emitted it. The reader rejected it because it applied the 24,704-code-point **canonical text** limit to the JSON envelope. This is a current writer/reader asymmetry even without historical data. [Interchange][ergon] · [Topic limits][limits]
- The HEAD converter could not semantically read current JSON. Its generic fallback turned the entire one-entry JSON representation into a different Topic in the tested case. If mixed-version readers or rollback must replay new values, the transition needs an explicit scope or compatibility disposition. [Converter][converter] · [Interchange][ergon]

## Historical compatibility requiring adjudication

- **UUID references and persisted JSON · C-01 / DR-3 and DR-4.** The corrected Ergon reader validates and discards the predecessor UUID. Two predecessor objects with identical entries and different IDs resolved to the same path and emitted identical current JSON. This preserves the ordered path and cannot preserve a UUID reference from the reconstructed value. The actual Task extensions carry the old UUID inside their Topic payload. Source tracing found no downstream Ergon/Pylai/Petasos UUID lookup from these extensions. The inspected Pylai FHIR identifiers use the raw Topic name, and the IU's UUID and unqualified designation remain distinct. Former Calliope structure, coordinates and itinerary accessors exposed Topic UUIDs, but no external caller or deployed UUID-keyed registry was established. The Solution Architect needs to disposition applicability and reference handling at the persisted Task boundary and any identified registry or client. The accepted qualified path remains the runtime identity. [Interchange][ergon] · [Pylai Task identifier][pylai] · [IU identifier][iu-id] · [Coordinates][coordinates] · [Reconciliation][reconciliation]
- **Actual generic historical JSON boundaries · C-01.** The FHIR-specific adapter does not run for embedded `ErgonPayload` Topics in ordinary `Pragma` JSON. An exact predecessor Topic fixture failed through the `Pragma` binding used by the Praxis/Erga cache and Ponos JSON routes, while a current fixture passed. A synthetic predecessor Topic in IU metadata also failed through the configured V001 persisted-record constructor. These are real readers with demonstrated historical-shape incompatibility. The presence and migration scope of existing rows or queued values are unresolved. Treat each affected boundary explicitly before relying on replay, including the scope of current writes and older readers. [Pragma][pragma] · [Praxis cache][cache] · [Ponos JSON route][ponos] · [V001 reader][v001-reader]
- **Native Java streams · C-01.** A predecessor Topic and a predecessor mask each failed in Java 21 with stream UID 1 versus local UID 2. Current proxy round trips passed. The inspected transport and persistence routes use FHIR or Jackson JSON and the Hot Rod workflow configuration uses a UTF-8 String marshaller. No supported live or durable native Java object-stream boundary carrying these types was established. Record this as a qualified compatibility obligation if such a boundary is identified. The replay establishes an implementation mismatch without establishing a migration requirement. [Topic proxy][topic] · [Mask proxy][mask] · [Hot Rod configuration][hotrod]
- **Previously accepted deterministic text.** HEAD accepted legacy plain `Alpha\Beta` as a literal backslash and normalized outer and per-segment padding. It also treated trailing periods as absent, so `Alpha.` selected like `Alpha` under Exact and Inclusive. The corrected Ergon/operational subject adapter rejects backslashes or per-segment padding, and rejects trailing empty segments. The selector factory also changes padded criteria from normalized matches to misses and rejects a trailing delimiter. Legacy first-equals parsing allowed another equals in the value, while the selector adapter rejects multiple unescaped equals. These are actual differences on tested or traceable predecessor inputs. Deployed use and approved treatment remain unresolved. [Historical adapter][historical-names] · [Selector factory][mask-factory]
- **Malformed or ambiguous text and intentional syntax.** An internal empty segment such as `Alpha..Beta` failed to form a predecessor Topic. An escaped period in a legacy selector failed Java RegEx evaluation after the historical path split and now rejects on construction. Nonstructural RegEx escapes such as `\d+` remained functional in the tested old and new selector paths. Empty or wildcard-only legacy selectors require established unrestricted intent under the design. A dotted action previously matched successive entries, and predecessor `Read[AB]` matched `ReadA` as Java RegEx. Such action strings now reject. Preserve or disposition any actual historical qualified, multi-entry or RegEx action requirements explicitly. The simple literal action control and the standard positional routing controls retain selection in the tested scope. [Selector factory][mask-factory] · [Security model][security] · [Design §§5 and 7][design]
- **Unknown historical applicability.** The old converter accepted some bracket-prefixed literals after failed JSON parsing, whereas the corrected reader treats them as JSON-shaped and rejects malformed documents. Old fallback text could not preserve arbitrary qualifiers in a raw value projection. No retained deployed fallback corpus, alias inventory, full persisted-selector corpus or qualified IU mapping establishes an obligation for those cases. `TopicSubscription` retains its own case-insensitive matching. No live routing or policy change was inferred from the test stimuli. [Original representation review][original] · [TopicSubscription][subscription] · [Reconciliation][reconciliation]
