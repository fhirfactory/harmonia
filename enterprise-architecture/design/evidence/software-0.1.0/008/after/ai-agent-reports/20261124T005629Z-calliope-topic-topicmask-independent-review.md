## Representation and compatibility

- **JSON.** In the Topic/TopicMask naming scope, direct Jackson annotation imports are in `Topic`, `TopicEntry`, `TopicMask`, `TopicMaskEntry` and the retained `TopicSubscription`. The builders, factories, parser, validator and evaluator have none. Related carriers such as `InformationSecurityContext`, `InformationUnitMask` and `OperationalMetadataMask` also have their own Jackson mappings. The first four model types emit ordered lists with raw fields. `Optional` stays in the domain API and nullable Strings or omitted fields carry presence on the wire. The probe compared complete Topic entries and mask fields for absent, empty and wildcard version expressions and confirmed the universal discriminator survives a correctly formed round trip. An empty Topic version normalises to absence. An empty qualifier/value RegEx remains a valid expression with no match against a valid nonempty field. Field validation, mask structure checks and RE2/J recompilation run on reconstruction. Malformed or ambiguous JSON can pass the wire boundary before those checks, as A-01 shows. See A-02 for loss in the containing security model.
