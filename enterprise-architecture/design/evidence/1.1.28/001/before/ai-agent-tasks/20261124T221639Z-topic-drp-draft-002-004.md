## 1. Establish the pre-1.0.0 development principle

The Solution Architect has established the following governing direction:

> Before Harmonia Software 1.0.0, the system is developed as one coherent evolving implementation of the accepted architecture.
>
> When an accepted architectural or software contract changes, all affected components, interfaces, integrations, tests and documentation must be refactored to conform to the new contract.
>
> Superseded APIs, implementations and intermediate designs carry no backward-compatibility obligation.
>
> A change is complete only when its affected dependencies are reconciled and applicable regression and integration verification succeeds.

This distinction is essential:

**Supporting already implemented components means updating them to the current contract, not maintaining compatibility with obsolete contracts.**

Do not interpret the absence of backward compatibility as permission to leave existing consumers broken.

The responsibility is to refactor the affected implementation coherently.

### Scope of refactoring

A contract change may affect:

- The changed component.
- Direct consumers.
- Indirect consumers.
- Interfaces and adapters.
- Persistence and interchange representations.
- Configuration.
- Integration behaviour.
- Tests and fixtures.
- Documentation.
- Build dependencies.

Determine the actual affected scope through dependency analysis.

Do not assume that recompilation alone demonstrates behavioural coherence.

### Release boundary

This principle applies before Harmonia Software 1.0.0.

It does not establish post-1.0.0 compatibility requirements.

Those will be governed by their applicable release and interface contracts.

## 2. Incorporate the principle into Software Development Praxis

Locate the existing authoritative Software Development Praxis documentation.

This is a completeness requirement, not a legacy compatibility requirement.

Do not introduce a general-purpose compatibility policy, migration framework or additional administrative process.
