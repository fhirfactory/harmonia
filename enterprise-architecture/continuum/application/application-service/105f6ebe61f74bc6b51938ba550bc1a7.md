# GovernedWriter

## Architectural content

### Approved 1.1.24 incorporation — resulting candidate pending

Full GovernedWriter conveys authorised CREATE, UPDATE and governed RETIRE of the full IU. RETIRE preserves governed history, retention, immutable versions and evidence; provider-native DELETE is not automatic physical destruction authority. Original MI-07 retains this mapping subject.

Persist/manage actual Content through the applicable PersistenceService, obtain its opaque reference, establish/update that reference in ContentMetadata and durably establish the corresponding Summary as **one coherent authoritative IU/version** (FC-01/04). Native Content-only or Summary-only partial/orphaned effects are not a successful full write. Responsible persistence workflow/adapter handles them under existing recovery rules. Logical atomicity does not mandate one native transaction, physical store or exact call order. There is no SummaryWriter UPDATE.

A directed/forced write never destructively overwrites preserved immutable history. An absent requested version may be established; an identical preserved state may already satisfy it. When integrity requires, Mnemosyne may establish a higher actual IU version, including a greater increment, and **returns the actual authoritative version on Success**. This changes neither Content Structure Version nor native payload version and transfers no per-IU concurrency from Mneme (AV-04).

Multi-site durable completion is required synchronously on Success (AV-03/04). Lost response/Indeterminate is investigated through authoritative GovernedReader(version=*) plus sufficient submitted-write correspondence and durability evidence; newer version alone is not proof (MI-06). Explicit version reads remain exact. No new seam transaction identifier, independent version counter or Mnemosyne-to-Mnemosyne IU arbitration is introduced.

Mneme reconciles Standard-Cache Summary and appropriate active manifestations with the actual outcome. It may safely refresh/invalidate caches but must preserve an executing Ergon's immutable version-specific input. Cache updates do not prove persistence.

All five contracts are synchronous governed request/response, with Calliope-owned factual Outcome (closed Success / Failure / Indeterminate and governed closed Reason vocabulary/extensions). Exact Reason members and stage codes remain deferred. Mnemosyne reports facts; Mneme determines consumer disposition without rewriting them. Transport/session timeout is not a factual operation Failure. Receipt, work acceptance, authoritative effect and end-to-end completion remain distinct.

Authentication and Themis policy apply: Readers require ACCESS + READ, SummarySearch invocation ACCESS + SEARCH and disclosed candidates ACCESS + READ, Writers CHANGE with the requested information operation. Protect identity, metadata, counts, pagination and other existence disclosures as well as Content. RequiredIU/SupportedIU capability matching grants no permission. Preserve source-near audit/provenance, Kleio mandatory capture authority/fail-closed obligations and Dokimasia/Provenance allocations; no blanket candidate event catalogue is promoted. Native database/query/provider values stay below the seam.

Every authoritative full or Summary mutation Success requires the applicable multi-site durable authoritative operation and actual resulting IU version, never cache success, local commit, replication queued or transport ACK. Immutable historical versions are preserved. Mneme retains individual-IU concurrency; eligible Mnemosyne instances must expose one coherent authoritative logical history or factual uncertainty. No extra seam transaction identifier or second version axis is introduced.
