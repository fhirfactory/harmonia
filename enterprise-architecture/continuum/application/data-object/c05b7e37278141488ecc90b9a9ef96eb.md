# Information Unit Metadata

## Architectural content

Information Unit Metadata holds four distinguishable concerns within one IU and
optional supplied relationships. It is a logical DataObject, not a second governed
management entity, nested IU, implementation Class or undifferentiated context store.

| Context | Accepted information and responsibility |
| --- | --- |
| ManagementContext | Mneme operational working information outside IU identity and represented Content. Embedded, referenced (including a cache-table reference), or hybrid; operational data may be explicitly transient. Client visibility grants no write authority. A lost transient reference is not durable truth. Mneme operational Version and Active Generation belong here. |
| InformationCoordinates | Four semantically distinct TopicID references: PersistenceGateway (named PersistenceService gateway/capability), GatewayEndpoint (named logical endpoint/parameter context), InformationLocation (logical location/node), InformationOwner (operational owner). Mnemosyne interprets them to resolve service and access context. They are names, not URLs, credentials, inline implementations, connection parameters or physical storage addresses. |
| SecurityContext | IU-side required action, compartment and other criteria using explicit Topics and/or TopicMasks. It is not the requesting Identity's permissions, Passport or PEP-Criteria. Themis owns policy and local PEP enforcement; a match alone grants no access. |
| LifecycleContext | Mneme–Mnemosyne persistence/lifecycle handshaking, preserving request, acceptance, commit and completion distinctions as required. No universal state machine or Content lifecycle owner; detailed vocabulary and preservation rules remain with governing contracts. |

**InformationCoordinates is independent of SecurityContext.** Operational owner,
gateway or location grants no clearance, compartment membership or read right.
Policy may separately consult a coordinate without turning it into a security rule.
Presence/population rules are contract-specific; no universal mandatory-coordinate
rule or configuration/deployment scheme is introduced.

| Version/generation concern | Home and meaning |
| --- | --- |
| Operational Version | ManagementContext: Mneme cache coherence, conflict/stale-write detection and optimistic concurrency. Does not substitute for Mnemosyne authoritative durable version progression. |
| Active Generation | ManagementContext: an individual successfully established active manifestation of the same IU in a Mneme cache environment/endpoint. Multiple generations may express the same operational Version. No new IU, representation or Content version follows. |
| Content Structure Version | InformationRepresentation.ContentMetadata: schema/structure version described by the Content Structure Topic. |
| Native Content instance version, if any | InformationRepresentation.Content: native payload contract; no synthetic native version is required. |

Active Generation is not a timestamp or a global counter. AX-05's successful-state,
failed/degraded-convergence and untrusted-coordination rules remain binding.
Failure to establish a generation changes neither the IU's governed information
state nor, by itself, an already established generation. No cache coherence,
distributed locking, invalidation, retry or generation-selection algorithm is chosen.

Temporal information stays with its meaning: clinical/business event/effective
times in Content; structure versions in ContentMetadata; needed working-cache
timestamps in ManagementContext; needed persistence/handshake times in LifecycleContext.
There is no mandatory TemporalContext or universal native payload lifecycle/history.
Retention holds, archival, immutable history, authorised disposition, recovery and
RETIRE versus physical destruction retain their distinct existing governance.

Optional **Relationships [0..*]** are creator/authorised-updater supplied IU-to-IU
or external-resource attributes/references. relatesTo, partOf and basedOn are
illustrative, not a mandatory vocabulary or a substitute for Provenance. Mneme
validates local reference acceptability under the applicable governed contract,
including suitable identity/authorised constraints; this is neither clinical-truth
validation nor target access permission. Mneme preserves remote references without
assuming responsibility for target existence, availability or correctness. There
is no automatic relationship inference, reciprocal maintenance, update propagation,
referent repair, distributed transaction or universal relationship database.

Provenance, AuditEvent, IU relationships and SecurityContext are distinct. Dokimasia
owns the established Provenance Management framework/lifecycle and independent
assurance; originating components use its existing Provenance Client Library.
Kleio retains AuditEvent management and authoritative audit capture. Mneme manages
active information; Mnemosyne establishes durable state. The IU carries appropriate
references/correlation without implementing evidence or lifecycle orchestration.
Request/session Passports/enforcement snapshots do not automatically become durable
IU Metadata or Content. Detailed field schemas, local-reference constraints and
provider acknowledgement/recovery vocabulary remain contract obligations.
