# TopicMask

## Architectural content

TopicMask is Harmonia's shared logical discrimination structure, comprising
regular-expression patterns applied **separately to corresponding individual
canonical-name elements** of a Topic. Applicable element expressions must match
under governed syntax/anchoring rules. It is neither one whole-name regex nor a
precomputed enumeration/set of TopicIDs. An element wildcard cannot silently span
adjacent dot-separated name elements. Matching can include subsequently introduced
Topics whose canonical-name elements satisfy the pattern without editing a list.
------- Legacy Content - Superseded ------- Finish ----

For example, `<BusinessDomain>.<StandardsBodyName>.InformationCompartment.<CompartmentName>`
illustrates a Topic hierarchy. `*.*.InformationCompartment.PersonalInformation*`
is illustrative shorthand only: an unconstrained element might use `.*` in actual
element-wise regex. Precise anchoring, escaping, missing/excess elements, variable
depth and serialised syntax remain with the applicable common match contract.
The example is not an implemented parser or prescribed regex dialect.

Publication/subscription, routing, discovery, security and other Topic-discriminating
Features reuse the same semantics. A match is a discrimination result; consuming
Features determine its consequence. Matching alone grants no access, publishes
nothing, schedules no delivery and selects no persistence provider. IU SecurityContext
is one consumer and does not own this common model.

### Approved immutable TopicMask contract — actual result pending review

A TopicMask has its own stable UUID and an immutable definition. Its UUID does not
influence matching. Changing type, containment behaviour or patterns creates a new
mask with a new UUID; old references retain meaning. It has **exactly one** basis:

| type | Explicitly sequenced pattern entries and matching subject |
| --- | --- |
| TopicNameBased | SequenceNumber → NameRegex; corresponding individual unqualified Topic names. |
| TopicCanonicalNameBased | SequenceNumber → EntryPattern(qualifierRegex, nameRegex); corresponding qualifier and name independently. |

One mask does not combine these two bases with AND/OR. Every regex applies to one
element; it cannot span adjacent path elements. There is no Topic/versionRegex axis.

| maskType | Containment meaning |
| --- | --- |
| Exact | Every specified level matches and candidate depth is exactly the mask depth. |
| Inclusive | Every specified level matches; further descendant levels are included. |

Thus a name-based inclusive Australia.ACT mask includes Australia.ACT.Canberra;
its exact counterpart includes only the two-level Topic. Typed qualifiers remain
first-class independently matchable discriminators in canonical-name mode.
An unrestricted mask is conceptually inclusive with unrestricted regex (.*);
standalone * is human shorthand, not valid Java regex. The expected default is
unrestricted, without accidental null-as-wildcard semantics. Exact root/unrestricted
wire encoding, cross-language regex dialect, escaping, anchoring and invalid-regex
handling remain bounded contracts requiring repeatable evaluation evidence.

InformationUnitMask, OperationalMetadataMask and PetasosParcelMask may contain or
reference TopicMasks for governed Topic-valued properties. SubscriptionStatement,
PublicationStatement and FilterStatement compose higher masks; they do not inherit
from TopicMask. Matching is neutral and confers no disclosure, publication, execution,
persistence or routing authority. Themis policy/actions/Passport remain distinct;
Passport is not an InformationUnitMask subclass. No higher-mask field catalogue,
absence semantics or Petasos framework design is supplied by this common primitive.
