# GovernedPersistenceFramework

## Architectural content

GovernedPersistenceFramework (GPF) is Mnemosyne's accepted fourth responsibility tier. It controls PersistenceService state and workflow, delegates and correlates operations, and may provide supervision, watchdogs, timeout handling and higher-level failure processing.

GPF and Persistence Adapter jointly realise PersistenceService: GPF supplies state/workflow control and the adapter supplies technology-specific execution and verification. Each Realization relationship records a contribution to that joint capability, not independent fulfilment by either tier. PersistenceService is not a sixth tier, and GPF is not all Mnemosyne governance or a mandatory separately deployed code framework.

GPF correlates delegation with service/workflow state while the adapter correlates native operations and acknowledgements. A watchdog expiry may justify reporting Indeterminate at this point; it proves neither failure nor success of an in-flight write. GPF must not reinterpret a factual adapter result or perform technology-specific verification on its behalf. Safe reconciliation/retry follows the governing operation contract; no universal state machine, timeout, retry algorithm or guaranteed eventual resolution is prescribed.

### Incorporation standing

Accepted parent DRP semantics, incorporated under the operative Task for 1.1.23/001. Actual resulting candidate confirmation remains pending. Earlier component/source qualifications remain independently in force.
