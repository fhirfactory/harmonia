# Mneme-Workflow-Cache

## Architectural content

Mneme's transient materialised processing-cache responsibility, realised by **embedded Infinispan LOCAL inside each applicable Ponos, DigitalTwin and Dokimasia execution JVM**. It stores the full/resolved working manifestation required by governed context loading. It is local per JVM, not a site-wide shared cache, remote Server cache, Hot Rod near cache or distributed L1 hybrid. No inter-JVM/site replication, ownership/affinity registry or cache-recovery subsystem is introduced.

Common Ergon owns context loading/unloading, checkpointing and execution recovery; Behaviour and Dokimasia Ergon reuse these facilities. GovernedReader attempts Content materialisation through Mneme/Mnemosyne (large-binary pass-by-reference exception retained). A summary alone does not establish materialised external Content. Concurrent executions may independently materialise the same immutable .input(); their outputs remain governed by existing Pragma/Praxis/Ergon rules. Existing DigitalTwin sequential Behaviour execution is unchanged.

Entries are bounded/transient under context validity, Themis isolation and Mneme operational Version/Active Generation semantics. Cache copies/instances and generations are not new authoritative IUs, Content versions or representations. New authoritative versions do not retroactively rewrite an executing version-specific immutable input. Context-save changes go through governed Mneme/full Writer, not raw write-through or SummaryWriter UPDATE.

After eviction, JVM/cache/site loss, common execution recovery reconstructs necessary context from authoritative information and durable work/checkpoints at the existing boundary. Do not resume inside a failed Ergon. Lost cache entries need not themselves be recovered; accepted work and acknowledged information must remain preserved. A checkpoint in a transient cache does not prove durability.

### Retained MC-01–MC-07 qualifications

- **MC-01:** Standard-Cache multi-site topology and active/active consistency need evidence; synchronous distribution/cross-site backup is not native linearizability or safe independent-cluster same-key concurrency.
- **MC-02:** Owner count/site placement, majority/partition/failover and continued governed work after one site loss remain unproved; Mneme retains state-transition concurrency obligations beyond cache operations.
- **MC-03:** Per-JVM memory bounds, safe eviction/lifetime relative to context load/unload/checkpoint and security isolation remain solution/deployment policy under existing Ergon semantics.
- **MC-04:** Durable propagation does not prove immediate replica read visibility. Exact-version/currentness, read-after-write and wait/fail/Indeterminate behaviour use Mneme–Mnemosyne and PersistenceService contracts; no cache affinity mechanism is invented.
- **MC-05:** Active/active N+1 (N > 0) is an architectural target, not a verified product guarantee. With only two physical sites, loss of one prevents **new multi-site durable write Success** without another eligible durable site or explicit owning NFR/persistence disposition. Never weaken Success or claim unqualified N+1 write continuity. Three-plus sites alone do not prove quorum/failover correctness.
- **MC-06:** Five-service reconciliation is deterministically incorporated: historical GovernedSearch identity is reused as sole GovernedSummarySearch, Summary Reader/Writer added, full Reader/Writer retained; no independent Summary IU or sixth method.
- **MC-07:** Existing capability/Feature contributions are reused. Physical remote-client/embedded ownership, observation, deployment and as-built integration remain downstream; no new module or implementation framework is selected.
