# Persistence Adapter

## Architectural content

Mnemosyne's fifth responsibility tier encapsulates selected provider technology. It performs delegated native operations, receives/interprets engine acknowledgements, correlates native requests/transactions, and performs supplementary reads or out-of-band verification when needed within the delegated operation sequence. It establishes and reports the operation's actual known result under that operation's completion contract.

Dispatch or a native ACK alone cannot establish authoritative success unless it satisfies the required completion evidence. An engine without credible verification for claimed operations is a suitability concern; Indeterminate is truthful current uncertainty, not an excuse for an unsuitable provider. No mandatory second read for every write or universal proof threshold is imposed.

Native schemas, IDs, revisions and correlation support the governed reconstruction and identity/version obligations without replacing them. The physical contract need not be IU-shaped. Search, transactions, indexes, traversal, bulk, history or other capabilities may be additive and attach only to actual supporting PersistenceServices; no universal parity, fabricated search support or one Interaction per native verb is created.

GPF controls workflow; the adapter owns technology-specific execution/verification. Both contribute jointly to PersistenceService. For a given IU, eligible Mnemosyne instances reach the same logical authoritative engine, which may have physical replicas. This permits no independent authoritative histories or transfer of IU-instance concurrency from Mneme.
