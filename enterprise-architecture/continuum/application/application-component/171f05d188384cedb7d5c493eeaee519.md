# Provenance Client Library

## Architectural content

Dokimasia provides this reusable architectural library responsibility for use by
Harmonia components and execution activities. It performs the common work of
Provenance creation, capture of relevant information/activity/context references,
and reporting or publishing Provenance into the Provenance Management framework.
The originating component generates Provenance through the library; Dokimasia
retains ownership of the framework and management/lifecycle of resulting information.

This is a logical ApplicationComponent representing the agreed reusable library,
not an implementation-level Java class/interface, additional execution framework,
runtime service or deployment boundary. Provision by Dokimasia asserts no runtime
containment, Java dependency or particular contract/transport. Existing Ponos,
Ergo/Ergon and governed information-management facilities remain in use.

Provenance references relevant InformationUnits, Pragma instances, execution
activities and associated Context without requiring embedded contents. Existing
identity/version/reference/governance semantics remain unchanged. Management uses
Mneme and authoritative durable persistence uses Mnemosyne; the library establishes
no independent storage and does not make publication success equivalent to persistence
or Assurance. It grants no assured component control over Assurance conclusions.
Kleio's Audit capture contract/library and AuditEvent responsibilities remain separate.

**Standing:** Candidate under HCRL 1.1.19-001 DR-18, with DR-19 Assurance constraints;
agreed intent is not formal candidate acceptance. Original versus linked new retry
Pragma, attempt representation, synchronous/asynchronous publication, acknowledgement/
recovery, Provenance schemas/cardinalities/lifecycle states and detailed client-library
contracts/deployment remain unresolved. No implementation is authorised.
