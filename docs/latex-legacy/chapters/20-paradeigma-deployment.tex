\section{Strict Production Isolation Invariants}

\begin{principlebox}{Paradeigma Production Isolation Invariant}
In accordance with Invariant 1:
\begin{enumerate}
    \item Production subprojects (\texttt{calliope}, \texttt{themis}, \texttt{hestia}, \texttt{petasos}, \texttt{energeia}, \texttt{pylai}, \texttt{iris}, \texttt{agora}) must \textbf{never} import or declare Maven dependencies on \texttt{net.fhirfactory.harmonia.paradeigma.*}.
    \item Production classes must not contain simulation toggle flags (e.g. \texttt{paradeigmaMode}, \texttt{simulationMode}, \texttt{syntheticRequest}, \texttt{isParadeigmaGenerated}).
    \item Production container images must not package simulator classes or scenario runners.
\end{enumerate}
\end{principlebox}

\section{Automated ArchUnit Verification}

This isolation rule is enforced continuously by the automated ArchUnit test suite (\texttt{ParadeigmaIsolationArchitectureTest} and \texttt{AgoraIsolationArchitectureTest}) in the CI/CD pipeline:
\begin{lstlisting}[language=bash, caption={Executing ArchUnit Isolation Test Suite}]
mvn test -pl paradeigma/paradeigma-test -am -Dtest="*ArchitectureTest" -Dsurefire.failIfNoSpecifiedTests=false
\end{lstlisting}

\section{Paradeigma Simulation Profile Deployment}

When testing in a dedicated staging or simulation environment, Paradeigma workloads are deployed as external client containers via the simulation overlay:
\begin{lstlisting}[language=bash, caption={Deploying Paradeigma Simulation Workloads}]
kubectl apply -k deployment/kubernetes/environments/simulation
\end{lstlisting}
