# Incremental RAD → common ArchiMate publication plan

**Proposed implementation slices, not authorisation to execute them.** Review the [mapping specification](rad-archimate-model-mapping.md), [catalogue](rad-archimate-mapping-catalogue.md) and [coverage findings](rad-archimate-coverage-assessment.md) before moving beyond the first bounded slice. The first slice is installed under the [release policy](architecture-release-policy.md) and [current release authority](../../../architecture-release.json). Later slices remain proposals and are not authorised by this installation.

## Common gate for every slice

Each accepted change set must apply the governed patch increment through the root release authority and shared helper, as defined in the release policy. Minor/major increments need an explicit governance decision. A slice is a coherent reviewable change set, not a license to increment a document counter instead of the Harmonia release. Preserve all established semantic IDs, aliases and visual IDs; allocate semantic identity only through an authorised identity register/crosswalk. Do not merge by names.

Every slice must (1) apply the governed release increment, (2) retain identity/history, (3) add one bounded architecture slice, (4) generate/update its stated shared-model Views, (5) validate all element/relationship/organisation references and endpoint/native-type agreement, (6) validate serialized XML offline against the Archi 5.9 bundled Open Exchange XSD, (7) produce a short changed-files/identities/coverage/gaps/test report with deterministic hashes and repeat-generation evidence, and (8) permit import and visual inspection in Archi before the next slice. Run required bounded repository architecture checks and relevant publisher checks. No schema PASS substitutes for visual review or source authority.

If a slice encounters an unestablished identity or semantic relation, stop that dependent portion and report the evidence. Other independent authorised work may proceed. Do not silently promote candidates, infer architecture to meet a slice quota, or declare final RAD coverage from file/heading counts.

and the 14 EC bindings from 1.0.3 remain intact. The 214 unresolved crosswalks,

Stop at that inspection gate before another publication slice.

Slices after the first are dependencies and review proposals, not a mandated big-bang timetable. Partition a row further whenever identities, source scope or visual size would make review difficult. Reuse existing elements across Views and domains; do not create separate Business/Application/Technology models. Component/report navigation should resolve to the same common semantic object and its incoming/outgoing relationships.

The publication plan does not change the Architecture Completion Programme or the runtime convergence sequence. It represents architecture after the applicable authority/identity decisions; it does not itself authorise missing architecture or runtime implementation. No further conversion is performed by this task.
