# Harmonia RAD → ArchiMate mapping catalogue

**Representation catalogue installed in the authorised release bundle, 2026-10-16; unresolved native mappings remain proposals requiring review.** This catalogue covers discovered construct kinds and supplements them with instance-level inventories. It allocates no architectural IDs and publishes no new semantics. “Direct” concerns semantic type compatibility only; it does not declare identity, documentation, relationships or automation ready. Read with the [mapping specification](rad-archimate-model-mapping.md).

## Reading the catalogue

Each row expands to **RAD Construct → Element → Relationship(s) → Identity → Documentation → Properties → Source → Expected Views**. The following shared identity/documentation/property profiles are part of every row citing them:

| Profile | Identity | Documentation | Properties / provenance |
| --- | --- | --- | --- |
| G | Existing governed ID exactly; otherwise explicit identity allocation/crosswalk required | Authoritative definition section plus material qualifications; absence reported | Only existing ID, domain/construct kind, status/scope, source path/section; source fingerprint in publication evidence |
| B | Domain03 §8 canonical/retained local ID and approved aliases; record key is navigation only | Source definition; capture summary is navigation evidence, not automatic replacement | G plus evidenced category, tier/FT, owner and unresolved dimensions; no tier from nesting |
| E | Existing baseline XML ID plus exact Reference ID; 14 EC allowlist only | Entire authoritative EC section body | Preserve all original properties; manifest records RAD source/section/hashes |
| A | Domain05 C/F/D/M IDs are documentary keys; approved source-to-semantic crosswalk required | Bounded register/DesignNote responsibility with exclusions and candidate qualifications | G plus actual accepted candidate standing, release scope when stated, cross-domain source evidence |
| R | Existing relationship ID or approved assertion crosswalk plus typed endpoint identities | Verbatim relationship rationale and semantic limits | Source predicate, direction, standing and provenance; no invented strength/read-write/authority |
| V | Existing deterministic visual namespace; View and semantic-object keys | Source-governed View explanation or publication purpose | Layout/navigation data only; no architecture identity or tier |

“No generated edge” means the source has not established a publishable native edge. Named potential relationships are conditional translations, not assertions of their existence. New Association predicate profiles require review under the specification. Classifications are exactly the requested six categories.

## Instance inventory and completeness boundary

`rad-archimate-source-inventory.json` accompanies this catalogue. It preserves all 705 Business-capture records, 462 captured relationship assertions and 73 catalogue contexts with existing keys, source evidence, proposed type/classification and publication gates. It also inventories 14 exact EC crosswalks, the 6/7/5/6/3 Motivation entries, AX-01–18, five foundational requirements, three external constraints, six Courses of Action, three Resources, four Value Streams, Domain05 register rows and source-section candidates in all eleven Information Families. It is a reconciliation aid, not a new semantic source or identity register. No inventory locator is a newly allocated architectural identity.

Identity/documentation profiles above apply to every instance in the inventory. Information Family heading candidates are explicitly **not** a count of approved objects: approval of a meaning does not approve every classification/relationship or create a heading-derived object. The inventory preserves source sections for review. Repeated Endpoint/Identifier/context names are not merged. Aggregate D/F/M rows are retained as bundles rather than converted mechanically. Source file fingerprints and a complete RADS source-path census make the inspected snapshot reproducible; documentary or candidate content remains distinguishable.
