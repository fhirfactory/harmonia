\chapter*{Executive Summary}
\addcontentsline{toc}{chapter}{Executive Summary}

The \textbf{Harmonia Health Information Exchange (HIE)} is a modular, high-availability, distributed healthcare integration platform engineered for HL7 FHIR Release 5 (R5) compliance, real-time HL7 v2 clinical data ingestion, sub-millisecond in-memory cached access, and resilient asynchronous workflow execution.

Modern healthcare ecosystems demand zero-loss event streaming, high-throughput message translation, resilient task state persistence, and fine-grained clinical data access. Harmonia resolves these challenges through a cohesive five-tier architectural design combining:
\begin{itemize}
    \item \textbf{Pylai Ingress \& Egress Gateways}: High-throughput bidirectional MLLP and REST ingestion and egress dispatch gateways for clinical events.
    \item \textbf{Petasos Messaging Subsystem}: High-availability, multi-broker active-active Apache ActiveMQ Artemis messaging cluster with native NIO journal replication and dynamic server-side message load balancing.
    \item \textbf{Energeia Workflow Engine}: Modular Apache Camel task activities (\textit{Erga}), structured workflow sequence orchestrators (\textit{Praxis}), and WildFly Jakarta EE 10 execution containers (\textit{Ponos}) operating on canonical task instances (\textit{Pragma}).
    \item \textbf{Hestia Data Services}: Low-latency in-memory data caching grid (\textit{Mneme}) backed by Infinispan 15+ and durable relational relational disk persistence (\textit{Mnemosyne}) backed by PostgreSQL 16+ and Spring Boot HAPI FHIR JPA.
    \item \textbf{Iris Presentation Services}: Dual-port Jakarta EE Backend-For-Frontend gateway (\textit{Iris BEFE}) and TypeScript / Vue 3 single-page applications for clinical exploration and operational administration.
\end{itemize}

\section*{ArchiMate 3.2 Architectural Modeling Framework}
\addcontentsline{toc}{section}{ArchiMate 3.2 Architectural Modeling Framework}

To ensure complete structural rigor, unambiguous domain boundaries, and formal traceability across business, application, and infrastructure tiers, this specification is authored strictly in accordance with \textbf{The Open Group ArchiMate 3.2 Standard}.

The architecture is described across six formal ArchiMate layers:
\begin{enumerate}
    \item \textbf{Motivation \& Strategy Layer}: Captures business stakeholders, regulatory drivers, architectural principles, high-level goals, and strategic interoperability capabilities.
    \item \textbf{Business Layer}: Models healthcare business actors, operational roles, clinical ingestion services, and business process lifecycles.
    \item \textbf{Application Layer}: Specifies the component landscape, internal module collaborations, application services, and canonical data object flows across the 26 Maven modules.
    \item \textbf{Data \& Information Layer}: Defines canonical information models, the \texttt{Pragma} task state machine, the \texttt{PetasosMessage} transport envelope, and the 14 supported FHIR R5 resource schemas.
    \item \textbf{Technology Layer}: Details infrastructure execution nodes, system software runtimes (WildFly, Artemis, Infinispan, PostgreSQL), communication paths, networks, and port allocations.
    \item \textbf{Physical \& Deployment Layer}: Documents multi-broker high-availability replication pairs, containerization topology, failover mechanics, and disaster recovery pathways.
\end{enumerate}
