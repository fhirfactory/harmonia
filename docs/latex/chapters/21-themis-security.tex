\section{Default-Deny Policy Invariant}

\begin{principlebox}{Default-Deny Security Enforcement}
In accordance with Invariant 6, all integration endpoints, task processors, and persistence operations default to \texttt{ThemisDecision.DENY}. Access is granted if and only if an explicit Themis policy rule evaluates to \texttt{PERMIT} for the authenticated security context.
\end{principlebox}

\section{The 4-Gate Defence-in-Depth Pipeline}

Security enforcement is applied at four successive gates:
\begin{enumerate}
    \item \textbf{Gate 1 --- Ingress Screening}: \texttt{FhirSecurityInterceptor} validates TLS certificates, JWT bearer tokens, and client IP origins.
    \item \textbf{Gate 2 --- Dispatch Authorization}: Ponos validates whether the authenticated principal has permission to publish to or consume from target Petasos queues.
    \item \textbf{Gate 3 --- Activity Execution}: Individual Ergon activities evaluate payload-specific security labels and user scopes.
    \item \textbf{Gate 4 --- Storage Compartment Enforcement}: Mnemosyne JPA mutators verify that the write operation complies with resource compartment and tenancy rules.
\end{enumerate}
