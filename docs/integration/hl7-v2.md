# HL7 v2.x Processing & Parsing `[IMPLEMENTED]`

Harmonia supports high-throughput, loss-free processing of HL7 v2.x clinical and administrative messages. Incoming HL7 v2 payloads are terminated at the Pylai gateway, parsed into structured metadata, encapsulated within canonical FHIR resources, and mapped to downstream FHIR R5 domain models.

---

## 1. Supported Message Families & Trigger Events `[IMPLEMENTED]`

Harmonia provides dedicated parsing, validation, and routing pipelines for four primary HL7 v2 message families:

| Message Family | Trigger Events | Primary Segment Profile | Processing Subsystem | Egress Targets |
| :--- | :--- | :--- | :--- | :--- |
| **ADT** (Admission, Discharge, Transfer) | `A01` (Admit), `A02` (Transfer), `A03` (Discharge), `A04` (Register), `A08` (Update Demographics), `A40` (Merge) | `MSH`, `EVN`, `PID`, `PV1`, `PV2`, `IN1`, `AL1` | `pylai-mllp-in` -> `energeia-ponos` -> `AdtDistributionErgon` | EMR, LMS, RIS/PACS |
| **MFN** (Master Files Notification) | `M01` (Staff/Practitioner), `M02` (Department/Location) | `MSH`, `MFI`, `MFE`, `STF`, `PRA`, `LOC` | `pylai-mllp-in` -> `Mfn2FhirBundle` | Mnemosyne Provider Registry |
| **ORM** (Order Entry) | `O01` (General Order) | `MSH`, `PID`, `PV1`, `ORC`, `OBR`, `DG1` | `pylai-mllp-in` -> `OrmRoutingErgon` | LMS, RIS/PACS |
| **ORU** (Observational Results) | `R01` (Unsolicited Result) | `MSH`, `PID`, `PV1`, `OBR`, `OBX` | `pylai-mllp-in` -> `OruProcessingErgon` | EMR Clinical Core |

## 2. HAPI HL7 v2 Architecture & Parsing Engine `[IMPLEMENTED]`

Harmonia utilizes the HAPI HL7 v2 parsing framework (`ca.uhn.hl7v2:hapi-structures-v24:2.3` and `hapi-base:2.3`):

### 2.1 Parser Initialization & ID Generation
```java
// IncomingAdtMessageProcessor.java
this.hapiContext = new DefaultHapiContext();
this.hapiContext.getParserConfiguration().setIdGenerator(new NanoTimeGenerator());
this.pipeParser = hapiContext.getPipeParser();
```
- **Context**: `DefaultHapiContext` initializes caching and validation contexts.
- **ID Generator**: `NanoTimeGenerator` ensures nanosecond precision for internal segment ID generation without thread lock contention.
- **PipeParser**: High-performance streaming delimiter parser optimized for `|`, `^`, `~`, `\`, `&`.

### 2.2 Segment Extraction via Terser
Field extraction utilizes HAPI's `Terser` path queries to support schema tolerance across v2.3, v2.3.1, and v2.4 dialects:

| Target Property | Terser Expression | Fallback Field | Description |
| :--- | :--- | :--- | :--- |
| `messageControlId` | `/MSH-10` | Random UUID | Unique message identifier generated by sending system. |
| `messageType` | `/MSH-9-1` | `ADT` | High-level message family. |
| `triggerEvent` | `/MSH-9-2` | `A01` | Specific clinical trigger event code. |
| `patientId` | `/PID-3-1` | `/PID-2` | Primary Medical Record Number (MRN) or National ID. |
| `patientFamilyName` | `/PID-5-1` | — | Patient surname. |
| `patientGivenName` | `/PID-5-2` | — | Patient first name. |
| `patientClass` | `/PV1-2` | `I` (Inpatient) | Encounter classification (Inpatient, Outpatient, Emergency). |
| `assignedLocation` | `/PV1-3-1` | `/PV1-3` | Ward or Point of Care identifier. |
| `room` / `bed` | `/PV1-3-2` / `/PV1-3-3` | — | Physical bed placement. |
| `visitNumber` | `/PV1-19` | — | Account or visit tracking identifier. |
| `attendingDoctor` | `/PV1-7-1` | `/PV1-7` | Attending physician identifier and name components. |

## 3. Canonical Transformation to FHIR R5 `[IMPLEMENTED]`

Rather than immediately flattening or discarding raw wire data, Harmonia follows a 2-step canonical wrapping pattern:

### 3.1 Step 1: Raw Payload Preservation (`Communication`)
The complete, uncorrupted HL7 pipe-delimited text is encapsulated within a FHIR R5 `Communication` resource:
```json
{
  "resourceType": "Communication",
  "id": "comm-98234-a01",
  "status": "completed",
  "category": [{
    "coding": [{
      "system": "http://terminology.hl7.org/CodeSystem/communication-category",
      "code": "notification"
    }]
  }],
  "subject": {
    "identifier": {
      "system": "urn:oid:1.2.3.4.5.6",
      "value": "PATIENT-MRN-90210"
    }
  },
  "payload": [{
    "contentString": "MSH|^~\\&|PAS|HOSPITAL|EMR|CLINICAL|20260917120000||ADT^A01|MSG-98234|P|2.4\rPID|1||MRN-90210||DOE^JOHN||19800512|M\rPV1|1|I|WARD-4B^ROOM-12^BED-1||||DR-4431^SMITH^ALICE||||||||||||VISIT-88411"
  }]
}
```

### 3.2 Step 2: Synthetic Workflow Task Generation (`Task`)
A synthetic routing `Task` is generated with `Task.input` referencing the `Communication` resource:
```json
{
  "resourceType": "Task",
  "id": "task-msg-98234",
  "status": "requested",
  "intent": "order",
  "code": {
    "coding": [{
      "system": "http://example.org/hie/task-type",
      "code": "ADT_DISTRIBUTION"
    }]
  },
  "input": [{
    "type": { "text": "RawHl7Communication" },
    "valueReference": { "reference": "Communication/comm-98234-a01" }
  }]
}
```

### 3.3 Step 3: Domain Model Extraction (`Adt2FhirMapper`)
Downstream in `energeia-erga`, `Adt2FhirMapper` unpacks the message into rich FHIR R5 domain resources:
- `PID` -> `Patient` (Identifiers, Name, Gender, BirthDate, Address).
- `PV1` -> `Encounter` (Status, Class, Period, Location, ServiceProvider, Participant).
- Bundled into a transaction `Bundle` for relational persistence into Mnemosyne.

## 4. HL7 Acknowledgment Semantics (ACK / NACK) `[IMPLEMENTED]`

Harmonia strictly complies with HL7 v2 Enhanced Mode Acknowledgment:

### 4.1 Positive Acceptance (`AA`)
Emitted only after dual-write confirmation (Mneme write + Petasos queue publish):
```hl7
MSH|^~\&|HARMONIA|HIE|PAS|HOSPITAL|20260917120001||ACK|ACK-98234|P|2.4
MSA|AA|MSG-98234|Message accepted and queued for distribution
```

### 4.2 Application Error (`AE`)
Emitted when downstream queue dispatch or cache persistence fails (REC-001):
```hl7
MSH|^~\&|HARMONIA|HIE|PAS|HOSPITAL|20260917120001||ACK|ACK-98234|P|2.4
MSA|AE|MSG-98234|Downstream messaging unavailable: Connection refused
ERR|^^^207&Application Internal Error&HL70357
```

### 4.3 Application Reject (`AR`)
Emitted on fatal structural malformations (e.g., unparseable MSH segment, missing MSH-9 or MSH-10):
```hl7
MSH|^~\&|HARMONIA|HIE|PAS|HOSPITAL|20260917120001||ACK|ACK-UNKNOWN|P|2.4
MSA|AR|UNKNOWN|Payload syntax error: Missing MSH segment delimiter
ERR|^^^100&Segment sequence error&HL70357
```
